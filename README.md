# UQAB

UQAB is a Tor pluggable transport that carries real Tor traffic inside fixed-size
cover records on a *persona* timetable — a schedule of record sizes and slot
intervals derived from real browsing, generated by a local LLM, or written by
hand. To an observer on the link, a UQAB session looks like a steady stream of
equal-sized records whose rhythm changes between states, instead of like Tor's
bursty, recognisable ACTIVE/IDLE pattern.

The repository contains the whole project described in the SRS, SDD and phase
plan: the transport, the persona pipeline, the evaluation pipeline, the
Windows browser app (a Min-derived Electron shell), and the A/B/C experiment
harness that measures whether persona cover actually hurts an observer's
ACTIVE/IDLE inference, and what it costs.

## Quick start (Linux / macOS / Windows)

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e .                                  # stdlib only; no runtime deps
python -m tunnel.certs                            # one-off mutual-TLS certificates
```

Open the app (development):

```bash
python -m app_api.server --host 127.0.0.1 --port 9170   # control API
python -m dashboard.server --port 8501                  # evaluation dashboard
cd app && npm install && npm start                      # Electron browser shell
```

Open the app without Tor (lab simulation, clearly labelled in the UI):

```bash
python -m lab.stack --persona high --socks-port 9150
```

Run the experiment that answers the research question:

```bash
python -m experiments.compare --loads 30      # A = plain, B = constant, C = persona
python -m experiments.report                  # markdown report + CSV appendix
```

## What each module does

| module | responsibility |
| --- | --- |
| `protocol/` | frame format: `type(1) length(2) payload`, DATA/PADDING/PING/CLOSE, hard 16 KiB cap |
| `cover/` | fixed-size record builder and the persona timetable scheduler (slot pacing, bursts, floor slots) |
| `tunnel/` | mutual TLS 1.3 between the PT client and the PT server, certificate generation |
| `security/` | fail-closed guard: any error closes the tunnel, never falls back to cleartext |
| `pt/` | the managed pluggable transport itself: SOCKS5 front end, session handshake, stats |
| `persona/` | persona schema, validator, static profiles, local-LLM generator with validation + fallback |
| `profile/` | opt-in clearnet capture, pcap features, k-means/Markov learner, privacy check, sampler |
| `analysis/` | pcap I/O, window features, logistic-regression and random-forest observers with CV and bootstrap CIs |
| `experiments/` | scripted browsing timeline, lab capture, run orchestration, A/B/C comparison, report |
| `storage/` | SQLite schema and queries (runs, page loads, scores, slot timing) |
| `dashboard/` | read-only HTML dashboard over the run database (inline SVG charts, no JS) |
| `app_api/` | control API (`/status`, `/start`, `/stop`, `/personas`, `/consent`, ...), engine supervisor, Tor controller |
| `app/` | Min-derived Electron browser: tabs, address bar, history, 1 Hz live panel, Start/Stop |
| `lab/` | Tor-free simulation stack for demonstrations and tests (see `docs/LAB_MODE.md`) |

## Tests

```bash
python -m pytest -q          # ~250 tests, no network, no Tor, no browser
python -m ruff check .
python -m mypy .
```

The suite covers the frame parser against malformed input, record size exactness,
slot timing accuracy, TLS 1.3 rejection paths, the full PT session over loopback,
the lab stack end to end, the control API lifecycle, persona validation and LLM
fallbacks, the profile privacy check, classifier accuracy on synthetic windows,
the dashboard routes and the packaging layout.
